# Change-spec:feat-L review 說明書去重載入(review-protocol.md + receiving-code-review ×3 → ×1)

## 0. 背景、目標、非目標

**現況**:feat-L profile 在 Phase 1、2、4 各載入一次 `harness/refs/review-protocol.md`(4,090 B)與 `superpowers:receiving-code-review` SKILL.md(量測時 6,132 B;現行 6.2.0 為 6,203 B)。三個 phase 是同一個連續 context——Phase 1 載入的內容在 Phase 2、4 到達時通常還在窗口裡,重複載入純屬浪費,合計 20,444 B(2 次多餘 × 兩檔)。

**目標**:同一 session 內這兩份「怎麼接收 review 意見」的說明書只完整載入一次;之後的引用點沿用 context 內既有內容,除非 context 壓縮已把它摘掉。

**非目標(行為白名單)**:三輪 review 的一切不動——Phase 1/2/4 各自 dispatch 的 reviewer、輪數上限 3、退出條件(無 P0 且 P1 ≤ 2)、receiving 三分類義務、severity 分級、round JSON 落檔,全部逐字保留。動的只有「載入指示」。

**機制核心**:在 feat.md 核心原則新增一條「一次載入」規則 + 明確的重載判準;manifest 把 Phase 2/4 的四筆條目改成 `condition` 條目(CLI 預設帳不計、worst 帳仍計,對齊 F2「靠 prompt 自律的規則要誠實記帳」的教訓)。

**改動位置注意**:source of truth 在 `~/.claude/`,`docs/harness/` 是鏡像。下面每一條都是改原檔,最後跑 `python scripts/sync-harness-mirror.py --fix` 同步鏡像;**不直接改 docs/harness/**。

## 2. Context 壓縮後的 fallback 路徑

三層兜底,由強到弱:

1. **重載判準主路徑**:核心原則 (a) 壓縮偵測——compaction 後對話開頭有 summary,機械可辨;命中即重 Read / 重 invoke,行為回到現狀,零損失。
2. **自檢兜底**:判準 (b) 要求「能複述關鍵結構」——門檻是逐項複述(A 節 5 步、B 節快篩 (a)-(d)、三分類 + forbidden responses),不是「記得有這回事」。summary 保留了「曾讀過」但壓掉細節時,這條會觸發重載。
3. **常駐契約兜底(最壞情況的底線)**:即使前兩層都失守,receiving 的三分類義務(`accepted` / `rejected_with_reason` / `needs_more_context`,絕不照單全收)**本來就常駐在 feat.md 核心原則「Receiving 紀律」條**,而 feat.md 是 scope=main 全程載入。最壞情況退化為「有分類契約、無完整說明書」,不會退化成照單全收。若連 feat.md 都被壓掉,那是既有的 resume 問題(`harness-context.py` 注入 + state.json 重讀 feat.md),與本改動無關且路徑已存在。

關鍵不對稱性:這條規則失守的兩個方向,「該沿用卻重載」= 回到現狀(只是沒省到);「該重載卻沿用」= 由第 2、3 層接住。沒有比現狀更糟的失敗模式會無兜底。

## 4. 這個改動可能打壞什麼

1. **判準 (b) 的自我評估失準**(最主要風險):模型高估自己「還記得」,summary 已壓掉細節仍沿用 → receiving 執行流於形式。這正是 F2「靠 prompt 自律的規則實測失守」點名的模式。緩解:§2 第 3 層常駐契約兜底 + manifest 保留 conditional 條目(不假裝已省下)+ §3.2-4 的壓縮情境抽驗。若抽驗發現失守,回退成本 = 把四筆 condition 拿掉,一個 commit。
2. **Phase 1 只讀了 A 節**:Phase 1 實際只「用到」A 節,若當時 Read 帶 limit 只讀半檔,Phase 4 沿用會缺 B 節。緩解:核心原則措辭已寫死「**完整**載入(讀全檔,含 B 節)」;檔案僅 4 KB,無部分讀的動機。
3. **與 using-superpowers「必 invoke」衝突**:skill 系統要求每次引用必 invoke。已用 harness 既有的「顯式覆寫」慣例標明(同 Phase 8 覆寫 finishing-a-development-branch 的先例),不是默默違反。
4. **superpowers 升版時序**:skill 在 session 中途升版,沿用的是 Phase 1 載入的舊版。這其實是 session 內一致性的優點;跨 session 無影響。
5. **研究資料口徑**:round3 及後續量測若拿 feat-L 載入帳做 before/after,要註明用預設帳還是 worst 帳——本改動讓兩者第一次出現分歧,漏註會做出假結論。
6. **弱模型 / goal_efficiency_mode 忽略規則**:忽略「沿用」→ 照舊重載 = 現狀,零 regression;忽略「重載判準」→ 由 §2 兜底。無新增的無兜底路徑。
