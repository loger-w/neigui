## 2. Fallback 路徑(context 壓縮導致內容已不在窗內)

**觸發訊號(任一即 fallback):**
1. §1.1(a) 的四項自檢 probe 任一寫不出 — probe 刻意選「可機械核對的逐字內容」(分類名、步驟動詞、(a)-(d) 代號),不是「我覺得我記得」。
2. 本 session 出現過 context 壓縮續接(summary 開場)— 此時**不做自檢直接重讀**,因為 summary 常保留「讀過該檔」的印象與名詞,卻丟失紀律內文,自檢有 false-pass 風險。

**動作:**
- review-protocol → `Read ~/.claude/harness/refs/review-protocol.md`(整檔,4KB 不值得分段)。
- receiving-code-review → 重新 `Skill(superpowers:receiving-code-review)`。
- 重讀後照常執行該輪 review;重讀不計入任何 cycle count、不算鐵則違規。

**Fail-safe 方向**:自檢設計成「寫不出就重讀」,最壞情況 = 每個 phase 都重讀 = 退回現狀成本,不會比現在更差;不存在「該讀而讀不到」的分支。

## 4. 這個改動可能打壞什麼

1. **Prompt 自律失守(最大風險)**:round 3 F2 已實證「靠 prompt 自律的規則實測失守」(manifest 內 phase 3 `_note` 就是先例)。自檢可能被跳過 — 沒重讀也沒自檢,Phase 4 的 receiving 劣化成照單全收。緩解:probe 設計成機械可核對;**回滾條件**:若後續 run 觀察到 finding 無 resolution 欄、或分類全 accepted 無任何 rationale,直接還原這四筆 manifest 條目與 feat.md 措辭(revert 單 commit 即可)。
2. **Compaction summary false-pass**:summary 留下名詞、丟掉紀律內文。已用「壓縮過即無條件重讀」堵住,但代價是壓縮頻繁的長 session 實省遠低於帳面 20,444 — **帳面節省不可當作已實現節省**,量測時要分開報。
3. **review-protocol.md 的共用性**:/mod /bug /refactor /perf 也引用它;若 §1.3 註記措辭不慎,可能誘導未定義自檢規則的 command 也跳過載入而無 fallback。已用「未定義者維持原載入行為」顯式封住;review 該行措辭時以此為 P0 判準。
4. **hook 提醒防線減弱**:phase 2/4 的 refs 注入行不再列 review-protocol.md — 若 agent 既忘了內容又忘了「該自檢」這條規則本身,失去最後一道機械提醒。這是本改動的本質 trade-off(提醒 = 重複載入的來源),接受並靠 §3.2 行為層核對兜底。
5. **superpowers 升版**:receiving-code-review 內容改版後 probe 關鍵句漂移 → 自檢恆失敗 → 每 phase 重讀,退化為現狀(fail-safe,不變壞);20,444 這個數字會隨版本漂,驗證時以 `harness_load_estimate.py` 實跑值為準,不寫死。
6. **測試紅**:`test_harness_phase_refs.py` / `test_harness_load_estimate.py` 若有對真 manifest 的期望值會紅 — 屬預期,§3.1 已列處置。
